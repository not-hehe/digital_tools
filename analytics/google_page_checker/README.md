# google_page_checker

Проверяет список сайтов и отвечает по каждому на вопрос: работает ли там
Google Analytics.

## Зачем это нужно было

У компании несколько сотен сайтов, и никто не мог сказать, на скольких из них
аналитика реально собирает данные. Проверять руками нереально, а поиск строки
GTM- по коду страницы даёт неверный ответ.

Вот три случая, где такой поиск ошибается:

- контейнер прописан в вёрстке, но удалён в интерфейсе GTM. Запрос за ним
  уходит и возвращает 404, данные никуда не идут;
- тег отключён конфигом платформы. Разметка на месте, запроса нет вообще;
- на странице стоит чужой скрипт (баннер согласия, чат, счётчик), который
  вызывает gtag без своего идентификатора. Своей аналитики у сайта нет.

Во всех трёх случаях поиск подстроки скажет, что аналитика есть.

## Как решено

Каждый сайт открывается в headless-Chromium, потому что значительная часть
установок приезжает через JavaScript уже после загрузки страницы. Пока
страница живёт, чекер слушает сеть и собирает улики, а потом взвешивает их
по силе.

| Улика | Что означает | Статус |
|---|---|---|
| Запросы вида /collect к серверу аналитики | счётчик отправляет данные | WORKING |
| Идентификатор установки в готовом DOM, хитов нет | тег есть, но не срабатывает | BROKEN |
| Только служебная телеметрия об ошибках библиотеки | нужна ручная проверка | SUSPICIOUS |
| Ничего из перечисленного | аналитики нет | NONE |
| Страница не открылась | смотри разбор отказов ниже | ERROR |

Отдельно чекер отличает сильные маркеры от слабых. Сильный - это
идентификатор установки: GTM-XXXX, G-XXXX, UA-XXXX-X. Слабый - упоминание без
идентификатора, вроде голого вызова gtag или ссылки на библиотеку. Слабые
маркеры установкой не считаются, потому что почти всегда принадлежат чужим
скриптам.

## Что оказалось неочевидным

**Одного прогона мало.** Сетевые запросы нестабильны: сайт, который в первый
раз не показал ни одного обращения к аналитике, во второй раз показывает.
Список проверяется несколько раз, результаты сливаются по силе улик, побеждает
самый убедительный.

**Ошибка открытия это не одно событие, а девять разных.** Мёртвая запись DNS,
устаревший TLS, закрытый порт, требование авторизации и мусор во входном файле
требуют разных действий. Чекер раскладывает отказы по видам и от вида зависит
поведение: повторять попытку или нет, пробовать другой адрес или нет. Домен без
записи DNS за паузу не починится, и тратить на него три попытки по 45 секунд
незачем.

**Universal Analytics больше не существует.** Google остановил сбор данных
в июле 2023 и удалил ресурсы в июле 2024. Тег UA-XXXXXXX-N в вёрстке физически
не может ничего отправить, это мёртвый код. Такие сайты выделены отдельно:
чинить там нечего, надо вычищать разметку.

## Запуск

```bash
cd analytics/google_page_checker
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
playwright install chromium

python3 tests/test_logic.py       # логика, браузер не нужен, около 2 секунд
python3 tests/test_e2e_local.py   # живой Chromium на локальных серверах
python3 main.py
```

Нужен Python 3.10 или новее.

Входной файл: data/input_urls.xlsx, колонка url. Рядом лежит
data/input_urls.example.xlsx с обезличенными адресами, чтобы можно было
запустить сразу.

Чтобы отчёт уходил в Mattermost, задайте адрес вебхука:

```bash
export GPC_MATTERMOST_WEBHOOK="адрес Incoming Webhook"
```

Без него прогон отработает штатно и просто не отправит сообщение.

## Что на выходе

Два отчёта. Краткий отвечает на вопрос, у скольких сайтов счётчик работает,
и раскладывает недоступные по причинам. Расширенный показывает по каждому
сайту найденные маркеры с куском вёрстки вокруг, пойманные запросы с кодами
ответов и причину, по которой тег не срабатывает.

В расширенном есть секция общих контейнеров: она показывает, где один и тот же
идентификатор стоит сразу на десятках сайтов. Это означает один шаблон
платформы и одно решение вместо десятков разборов.
