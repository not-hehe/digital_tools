# digital_tools

Рабочие инструменты для веб-аналитики и автоматизации рутины. Каждый проект
вырос из конкретной задачи, которую надо было закрыть, а не из желания
попробовать технологию.

Все примеры адресов в коде и тестах обезличены.

## Что здесь лежит

### analytics/google_page_checker

Массовая проверка сайтов на наличие работающей Google Analytics.

Задача звучит просто, пока не начнёшь её решать. Тег в коде страницы не значит,
что счётчик работает: контейнер могут удалить в GTM, отключить конфигом, или
это вообще чужой скрипт упомянул gtag без своего идентификатора. Поэтому чекер
не ищет подстроку в HTML, а собирает улики разной силы и взвешивает их:

1. реальные обращения к серверу аналитики - счётчик работает;
2. идентификатор установки в готовом DOM - тег есть, но не срабатывает;
3. служебная телеметрия об ошибках библиотеки - повод посмотреть руками.

Каждый сайт открывается в headless-браузере, потому что половина установок
приезжает через JS уже после загрузки страницы. Список проверяется несколько
раз подряд, результаты сливаются по силе улик: сетевые запросы нестабильны, и
один прогон регулярно врёт.

Список сайтов берётся из общей Google-таблицы с колонками по контурам сети,
в Mattermost уходит короткая сводка. Playwright, asyncio, 31 тест логики без
браузера плюс проверки на живом Chromium с локальными серверами.

Подробный разбор решений лежит в [docs/README.md](analytics/google_page_checker/docs/README.md):
там же написано, какие гипотезы оказались неверными и почему.

### analytics/attribution

Тег атрибуции для сайта с поддоменами, ставится через тег-менеджер.

Маркетингу нужно было знать, откуда пришёл клиент, оформивший заказ, даже если
между первым переходом и покупкой прошли месяцы. Тег помнит последний значимый
источник в пяти куках на весь домен: рекламная метка главнее реферера, переходы
внутри сайта источник не трогают, прямой заход только продлевает срок. Сверху
считается бизнес-канал по справочнику партнёров и правилам, чтобы кука сразу
ложилась в нужную строку отчёта.

Чистый JavaScript в одном файле, без зависимостей, сборка terser меньше 5 КБ.
40 тестов гоняют тег целиком в песочнице vm, и по исходнику, и по сборке.
Справочники в репозитории - пример: домен, партнёры и кампании обезличены.

### automation/main_domain_checker

Мониторинг доступности доменов с оповещением в Mattermost.

Проверяет список адресов раз в пять минут. Падение подтверждается тремя
неудачными прогонами подряд, иначе одиночное сетевое моргание поднимает
ложную тревогу, а при таком интервале один упавший сайт дал бы 288 сообщений
в сутки. В канал идёт массовое падение - несколько доменов в одном окне -
сразу, одиночное только после долгого отказа; всё остальное остаётся
в текстовом логе прогонов. Пороги подобраны по двум неделям обкатки, а не
рассуждением.

Замер на реальном списке: 366 адресов за 14.5 секунды при пуле в 100 потоков.
Задача целиком упирается в ожидание сети, на процессор уходит около трёх
секунд из этих четырнадцати, поэтому язык здесь ничего не решает.

Список доменов живёт в Google-таблице: колонка внешнего контура, внутреннего
и колонка давно лежащих сайтов. О последних канал молчит, пока какой-нибудь
из них не оживёт. Причина отказа в сообщении написана простыми словами, а не
кодом исключения.

Запускается башем по расписанию: `run.sh` делает один прогон и выходит,
планировщика внутри нет.

### automation/collector_checker

Мониторинг коллекторов веб-аналитики с оповещением в Telegram.

Младший брат main_domain_checker под другие правила: 15 адресов вместо сотен,
запуск раз в минуту, одна попытка на адрес. Первое падение уходит в чат
сразу, дальше пока коллектор лежит напоминание раз в 5 минут ровным шагом
от первого падения, а подъём сообщается сразу. Упавший и поднявшийся между
двумя напоминаниями в чат не попадает. Коллектор проверяется пустым GET без
хита: он отвечает 200 и пикселем, в аналитику при этом ничего не пишется.

Состояние и журнал хранятся обычным текстом, причины отказов живут только
в журнале: заказчику важен факт падения, а не его класс.

### automation/TV_dont_sleep

Расширение Firefox для телевизоров с дашбордами: листает вкладки по таймеру,
обновляет каждую перед показом и не даёт экрану уснуть через Screen Wake Lock.

## Стек

Python: Playwright и asyncio для браузерных проверок, requests и пул потоков
для сетевых, списки адресов из Google-таблицы CSV-выгрузкой на стандартной
библиотеке, cron как планировщик. JavaScript для тега атрибуции и расширения
браузера. Bash для обвязки и запуска.

Версии Python по проектам разные и указаны в их README. Общее правило: если
проект поедет на чужой сервер, синтаксис держим совместимым вниз.

## Как устроен репозиторий

```
analytics/     проверки и парсеры для веб-аналитики
automation/    автоматизация рутины
shared/        общие модули
```

У каждого проекта свой README с описанием задачи и командами запуска.

## Секреты и данные

Токены, вебхуки и пароли в репозиторий не попадают. Каждый проект читает их из
переменных окружения, рядом лежит .env.example с перечнем нужных имён.

Списки адресов живут в Google-таблице, ссылка на неё тоже секрет: в образцах
настроек (.env.example, secrets/sheet_url.example.txt) стоит ссылка-пример,
которую нужно заменить на свою. Результаты прогонов не коммитятся.
