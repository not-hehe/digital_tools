# digital_tools

Рабочие инструменты для веб-аналитики и автоматизации рутины. Каждый проект
вырос из конкретной задачи, которую надо было закрыть, а не из желания
попробовать технологию.

Все примеры адресов в коде и тестах обезличены.

## Что здесь лежит

### analytics/google_page_checker

Массовая проверка сайтов на наличие работающей Google Analytics.

Задача звучит просто, пока не начнёшь её решать. Тег в коде страницы не значит,
что счётчик работает: контейнер могут удалить в GTM, отключить конфигом, или
это вообще чужой скрипт упомянул gtag без своего идентификатора. Поэтому чекер
не ищет подстроку в HTML, а собирает улики разной силы и взвешивает их:

1. реальные обращения к серверу аналитики - счётчик работает;
2. идентификатор установки в готовом DOM - тег есть, но не срабатывает;
3. служебная телеметрия об ошибках библиотеки - повод посмотреть руками.

Каждый сайт открывается в headless-браузере, потому что половина установок
приезжает через JS уже после загрузки страницы. Список проверяется несколько
раз подряд, результаты сливаются по силе улик: сетевые запросы нестабильны, и
один прогон регулярно врёт.

Playwright, asyncio, 28 тестов логики без браузера плюс проверки на живом
Chromium с локальными серверами.

Подробный разбор решений лежит в [docs/README.md](analytics/google_page_checker/docs/README.md):
там же написано, какие гипотезы оказались неверными и почему.

### automation/domain_checker

Мониторинг доступности доменов с оповещением в Mattermost.

Проверяет список адресов раз в пять минут и пишет в канал, только когда
состояние изменилось: сайт лёг или поднялся. Падение подтверждается двумя
неудачными прогонами подряд, иначе одиночное сетевое моргание поднимает
ложную тревогу, а при таком интервале один упавший сайт дал бы 288 сообщений
в сутки.

Замер на реальном списке: 366 адресов за 14.5 секунды при пуле в 100 потоков.
Задача целиком упирается в ожидание сети, на процессор уходит около трёх
секунд из этих четырнадцати, поэтому язык здесь ничего не решает.

Запускается как таск Airflow. Ядро от Airflow не зависит и гоняется из
командной строки.

### automation/TV_dont_sleep

Расширение Firefox для телевизоров с дашбордами: листает вкладки по таймеру,
обновляет каждую перед показом и не даёт экрану уснуть через Screen Wake Lock.

## Стек

Python: Playwright и asyncio для браузерных проверок, requests и пул потоков
для сетевых, pandas и openpyxl для чтения входных списков, Airflow как
планировщик. JavaScript для расширения браузера. Bash для обвязки и запуска.

Версии Python по проектам разные и указаны в их README. Общее правило: если
проект поедет на чужой сервер, синтаксис держим совместимым вниз.

## Как устроен репозиторий

```
analytics/     проверки и парсеры для веб-аналитики
automation/    автоматизация рутины
shared/        общие модули
```

У каждого проекта свой README с описанием задачи и командами запуска.

## Секреты и данные

Токены, вебхуки и пароли в репозиторий не попадают. Каждый проект читает их из
переменных окружения, рядом лежит .env.example с перечнем нужных имён.

Входные списки адресов и результаты прогонов тоже не коммитятся. Вместо них
в data/ лежит input_urls.example.xlsx: тот же формат, обезличенные адреса,
достаточно чтобы запустить и посмотреть, как работает.
